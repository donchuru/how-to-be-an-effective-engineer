1. Read the documentation
2. Talk to existing users(ask a senior dev) + take a notepad
3. Take a look at the unit tests -> they will show you how the modules work

If you don't have any of these, 
1. Set up a development envrironment locally (DO NOT TEST IN PRODUCTION)
2. Try to mess around with the code and break the code. This will help you practice
3. Set breakpoints and step through the code. Take notes as you step through
4. Create little tests and make sure methods do what you think they do. If they don't, find out why
5. Document everything you learn

Along the way, create opportunities for learning i.e. when you go to fix a problem, write a unit test for it


### Tips from Andreas Kling
To get better at reading code:
  - interact with it while reading it. Build the code, add prints, reoder it the way you would naturally do it, etc. You will understand so much more of the code if you interact with it.
  - read (as in the point above) a lot of codebases. See how different things are implemented. Read LOTS of code. As a beginner, quantity > quality. Write lots, read lots
  - talk with experts of the codebases you are reading (maintainers, etc)
