#### My 5 step process to coding interviews
1. Come up with a conceptual solution. Piece together the individual bits of logic that help you get to a solution in your head.
2. Write your strategy down. Sometimes this is easier with pseudocode (although pseudocode is looked down upon in interviews)
3. Walk through the strategy/pseudocode to iron out bugs (there will ALWAYS be bugs so this is very important)
    - helps if you can step through with some extra test cases
4. Write the actual code
    - use extra test cases that you think will break your code
5. Analyze the time complexity of your solution
    - If you need to optimize, go back to step one

#### Tips from Andreas Kling
- Get good at the fundamentals (data structures and algorithms). Write pet projects as practice for this (rather than do a lot of challenges)
- During an interview, never give up no matter how hard the question is. \
Write the crappiest solution that works if you have to (don't worry about its time/space complexity as long as it works)
